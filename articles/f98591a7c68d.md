**Key Points:**
*   **グラフ理論の重要性**: 競技プログラミングにおいて、現実世界の問題（ネットワーク、経路探索、タスクスケジューリングなど）をモデル化するための根幹を成すのがグラフ理論である。
*   **アルゴリズムの多様性**: グラフの探索、最短経路、最小全域木、ネットワークフローなど、目的と制約に応じた多種多様なアルゴリズムが存在し、それぞれの特性を理解することが不可欠である。
*   **計算量の見積もり**: 競技プログラミングにおいては、実行時間制限（通常2秒程度）やメモリ制限内に収めるために、時間計算量および空間計算量を正確に見積もることが極めて重要である。一般的に $10^8$ 回程度の演算が時間制限の目安となる [cite: 1]。

競技プログラミング（競プロ）は、与えられた数学的・論理的課題に対し、制約時間およびメモリ空間内で正確な解を出力するプログラムを構築する競技である。その中でも「グラフ（Graph）」は、頂点（Node / Vertex）と辺（Edge）を用いて対象間の関係性を表現する強力なデータ構造であり、出題頻度や難易度ともに中核をなすテーマの一つである [cite: 2, 3]。本稿では、競技プログラミングにおいて必須となる主要なグラフアルゴリズムについて、その背景理論、時間計算量・空間計算量の解析、および具体的な実装例（主にC++およびPython）を網羅的に解説する [cite: 1, 4, 5]。

## 2. グラフの表現方法

グラフ $G = (V, E)$ をコンピュータ上で扱うためには、主に「隣接リスト」と「隣接行列」の2つのデータ構造が用いられる。競技プログラミングでは、入力されるグラフが密（Dense: $E \approx V^2$）であるか疎（Sparse: $E \approx V$）であるかによって適切な表現方法を選択する必要がある [cite: 4]。

### 2.1 隣接リスト (Adjacency List)

**説明**:
各頂点に対して、その頂点から直接辺が伸びている（隣接している）頂点のリストを保持する表現方法である。重み付きグラフの場合は、隣接する頂点番号と辺の重みのペアを保持する [cite: 6]。多くの競技プログラミングのグラフ問題では、頂点数 $V \le 10^5$ に対して辺数 $E \le 10^5$ 程度といった疎なグラフが与えられるため、隣接リストが標準的に用いられる。

**時間計算量**:
*   頂点 $u$ から $v$ への辺の追加: $O(1)$
*   頂点 $u$ に隣接する全頂点の走査: $O(\text{deg}(u))$ （$\text{deg}(u)$ は頂点 $u$ の次数）
*   頂点 $u$ と $v$ を結ぶ辺の存在判定: $O(\text{deg}(u))$

**空間計算量**:
$O(V + E)$。必要なメモリはグラフに存在する辺の数に比例するため、疎グラフにおいて極めてメモリ効率が良い [cite: 4]。

**実装例 (C++)**:
```cpp
#include <iostream>
#include <vector>

// 重み付き辺の構造体
struct Edge {
    int to;
    long long weight;
};

int main() {
    int V = 5; // 頂点数
    // 隣接リストの宣言: graph[u] は頂点 u から出る辺のリスト
    std::vector<std::vector<Edge>> graph(V);

    // 辺の追加 (0から1へ、重み10)
    graph.push_back({1, 10});
    // 無向グラフの場合は逆向きも追加する
    graph[cite: 7].push_back({0, 10});

    return 0;
}
```

### 2.2 隣接行列 (Adjacency Matrix)

**説明**:
$V \times V$ の2次元配列を用い、行 $u$ と列 $v$ の要素に、頂点 $u$ と頂点 $v$ を結ぶ辺の重み（辺が存在しない場合は特別な値、例えば $\infty$）を格納する表現である。頂点間の接続関係を高速に参照したい場合や、頂点数 $V$ が比較的小さい場合（$V \le 1000$ 程度）に用いられる [cite: 4]。

**時間計算量**:
*   頂点 $u$ から $v$ への辺の追加: $O(1)$
*   頂点 $u$ に隣接する全頂点の走査: $O(V)$
*   頂点 $u$ と $v$ を結ぶ辺の存在判定: $O(1)$

**空間計算量**:
$O(V^2)$。辺の数にかかわらず $V \times V$ のメモリを消費するため、$V$ が大きい場合はメモリ制限超過（MLE）の原因となる。

## 3. グラフの探索 (DFS, BFS)

グラフ探索は、ある頂点から出発して到達可能な頂点を体系的に巡回するアルゴリズムであり、多くの応用アルゴリズム（最短経路、連結成分分解など）の基礎となる [cite: 8]。

### 3.1 深さ優先探索 (Depth-First Search: DFS)

**説明**:
DFSは、現在いる頂点から行けるところまで深く進み、それ以上進めなくなったら直前の分岐点まで戻る（バックトラックする）という手順でグラフを探索する [cite: 8]。再帰関数（Call Stack）を用いるか、明示的なスタック（Stack）を用いて実装される。迷路の探索、連結成分の個数のカウント、サイクルの検出などに有効である [cite: 4, 6]。

**時間計算量**: $O(V + E)$。各頂点は最大1回訪問され、各辺も最大1回（無向グラフなら2回）調べられるためである [cite: 4]。
**空間計算量**: $O(V)$。再帰呼び出しの深さ、または訪問済みを管理する配列のサイズに依存する。

**実装例 (C++)**:
```cpp
#include <iostream>
#include <vector>

std::vector<std::vector<int>> graph;
std::vector<bool> visited;

void dfs(int u) {
    visited[u] = true;
    std::cout << "Visited: " << u << std::endl;
    for (int v : graph[u]) {
        if (!visited[v]) {
            dfs(v);
        }
    }
}

int main() {
    int V = 4;
    graph.resize(V);
    visited.assign(V, false);
    
    // グラフの構築
    graph = {1, 2};
    graph[cite: 7] = {0, 3};
    graph[cite: 2] = {0, 3};
    graph[cite: 9] = {1, 2};
    
    dfs(0); // 頂点0から探索開始
    return 0;
}
```

### 3.2 幅優先探索 (Breadth-First Search: BFS)

**説明**:
BFSは、始点から近い（辺の数が少ない）頂点から順に同心円状に探索を進めるアルゴリズムである [cite: 8, 10]。キュー（Queue）というデータ構造（先入れ先出し、FIFO）を用いて実装される。すべての辺の重みが同一（例えば重み1）である場合、始点から各頂点への最短経路（最短ステップ数）を求めることができる [cite: 8, 10]。

**時間計算量**: $O(V + E)$。各頂点は一度だけキューに追加・取り出され、その際に接続する辺が調べられる [cite: 10]。
**空間計算量**: $O(V)$。キューに格納される最大頂点数、および距離や訪問状況を管理する配列のサイズに依存する [cite: 10]。

**実装例 (Python)** [cite: 10]:
```python
from collections import deque

def bfs(graph, start, n):
    # 最短距離を格納するリスト。初期値は-1 (未訪問)
    dist = [-1] * n
    queue = deque([start])
    dist[start] = 0
    
    while queue:
        u = queue.popleft()
        for v in graph[u]:
            if dist[v] == -1: # 未訪問の場合
                dist[v] = dist[u] + 1
                queue.append(v)
    return dist

# 使用例
n = 4
graph = [[cite: 2, 7], [cite: 9], [cite: 9], [cite: 2, 7]]
distances = bfs(graph, 0, n)
print(distances) # 出力: [cite: 2, 7]
```

## 4. 最短経路アルゴリズム

ある頂点から別の頂点へ移動する際の経路のうち、辺の重みの総和が最小となるものを求める問題である。グラフの性質（負の重みの辺が存在するか、単一始点か全点対か）によって使用するアルゴリズムが異なる [cite: 11, 12]。

### 4.1 Dijkstra法 (ダイクストラ法)

**説明**:
負のコストを持つ辺が存在しないグラフにおいて、単一の始点から他のすべての頂点への最短経路を求めるアルゴリズムである [cite: 3, 11]。始点からの最短距離が確定した頂点に隣接する頂点の距離を計算・更新し、未確定の頂点の中で最も距離が短いものを次に確定させるという貪欲法（Greedy Algorithm）に基づく [cite: 11]。
実装には、距離の最小値を高速に取り出せる「優先度付きキュー（Priority Queue / Heap）」を用いるのが一般的である。

**時間計算量**: $O(E \log V)$。各辺を評価する際に優先度付きキューの更新に $O(\log V)$ かかるためである [cite: 3]。
**空間計算量**: $O(V + E)$。隣接リストと距離配列、優先度付きキューのためのメモリ。

**実装例 (C++)**:
```cpp
#include <iostream>
#include <vector>
#include <queue>

using namespace std;

const long long INF = 1e18; // 十分に大きな値

struct Edge {
    int to;
    long long weight;
};

// 始点sから各頂点への最短距離を返す
vector<long long> dijkstra(int V, const vector<vector<Edge>>& graph, int s) {
    vector<long long> dist(V, INF);
    // (最短距離, 頂点番号) のペアを保持する優先度付きキュー（距離が小さい順）
    priority_queue<pair<long long, int>, vector<pair<long long, int>>, greater<pair<long long, int>>> pq;
    
    dist[s] = 0;
    pq.push({0, s});
    
    while (!pq.empty()) {
        auto [d, u] = pq.top();
        pq.pop();
        
        // すでにより短い経路が見つかっていればスキップ
        if (d > dist[u]) continue;
        
        for (const auto& edge : graph[u]) {
            if (dist[u] + edge.weight < dist[edge.to]) {
                dist[edge.to] = dist[u] + edge.weight;
                pq.push({dist[edge.to], edge.to});
            }
        }
    }
    return dist;
}
```

### 4.2 Bellman-Ford法 (ベルマンフォード法)

**説明**:
負の重みを持つ辺が含まれるグラフに対する単一始点最短経路アルゴリズムである [cite: 11, 13]。すべての辺に対して「緩和（Relaxation）」操作（$dist[v] = \min(dist[v], dist[u] + weight)$）を行うプロセスを最大 $V-1$ 回繰り返す [cite: 13, 14]。
グラフ内に負の閉路（Negative Cycle: 一周するとコストが負になるサイクル）が存在する場合、その閉路を通り続けることで距離を無限に小さくできるため、最短経路は定まらない。Bellman-Ford法は $V$ 回目の反復でも距離の更新が発生するかどうかを確認することで、負の閉路を検出できるという強力な利点がある [cite: 13, 14]。

**時間計算量**: $O(V \cdot E)$。すべての辺に対する操作を $V$ 回繰り返すためである [cite: 13]。
**空間計算量**: $O(V)$。距離を記録する配列のみ（グラフ自体の保存を除く） [cite: 13]。

**実装例 (C++)** [cite: 14]:
```cpp
#include <iostream>
#include <vector>

using namespace std;

const long long INF = 1e18;

struct Edge {
    int from;
    int to;
    long long cost;
};

// 負の閉路が存在する場合は true を返す
bool bellman_ford(int V, int s, const vector<Edge>& edges, vector<long long>& dist) {
    dist.assign(V, INF);
    dist[s] = 0;
    
    // V 回ループを回す
    for (int i = 0; i < V; ++i) {
        bool changed = false;
        for (const auto& e : edges) {
            if (dist[e.from] != INF && dist[e.from] + e.cost < dist[e.to]) {
                dist[e.to] = dist[e.from] + e.cost;
                changed = true;
                
                // V 回目のループで更新が発生した場合、負の閉路が存在する
                if (i == V - 1) return true;
            }
        }
        // 更新が発生しなければ終了してよい
        if (!changed) break;
    }
    return false;
}
```

### 4.3 Floyd-Warshall法 (ワーシャルフロイド法)

**説明**:
グラフ内の「すべての2頂点の組み合わせ（全点対）」間の最短経路を求めるアルゴリズムである [cite: 11, 12]。動的計画法（Dynamic Programming: DP）の概念に基づいており、「頂点 $k$ を経由することで、頂点 $i$ から頂点 $j$ への最短距離が更新できるか？」という局所的最適化を全体に適用していく [cite: 12]。
負のコストの辺があっても動作し、対角成分（自分自身への距離）が負になることを確認することで負の閉路も検出可能である [cite: 11]。

**時間計算量**: $O(V^3)$。3重のforループによって構成されるため [cite: 12, 15]。$V \le 300 \sim 400$ 程度の制約の際に適用可能である [cite: 15]。
**空間計算量**: $O(V^2)$。2次元配列で頂点間の距離を保持するため。

**実装例 (Python)** [cite: 12]:
```python
def warshall_floyd(V, dist):
    # dist[i][j] は初期状態として辺の重み、辺がない場合はINF、i==jの場合は0とする
    for k in range(V):
        for i in range(V):
            for j in range(V):
                # kを経由した方が距離が短ければ更新
                if dist[i][k] + dist[k][j] < dist[i][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]
    
    # 負の閉路検出
    for i in range(V):
        if dist[i][i] < 0:
            return True # 負の閉路が存在
    return False
```

## 5. 最小全域木 (Minimum Spanning Tree: MST)

無向で連結な重み付きグラフにおいて、すべての頂点を連結し、かつ閉路を含まない部分グラフ（全域木）のうち、辺の重みの総和が最小となるものを最小全域木（MST）と呼ぶ [cite: 16, 17]。ネットワークの構築費用を最小化するような問題に適用される。

### 5.1 Kruskal法 (クラスカル法)

**説明**:
すべての辺をコストの昇順（小さい順）にソートし、小さい辺から順に採用していく貪欲法アルゴリズムである [cite: 17, 18]。ただし、辺を追加した際に閉路（サイクル）が形成されてはならない。閉路形成の判定には、「Union-Find（素集合データ構造）」を用いるのが標準的かつ極めて効率的である [cite: 17, 19]。両端の頂点がすでに同じグループ（連結成分）に属している場合、その辺を追加すると閉路ができるため破棄する [cite: 17, 18]。

**時間計算量**: $O(E \log E)$ または $O(E \log V)$。辺のソートに $O(E \log E)$ かかり、Union-Findの操作はアッカーマン関数の逆関数 $\alpha$ を用いてほぼ $O(1)$ とみなせるため、ソートの計算量が支配的となる [cite: 16]。
**空間計算量**: $O(V + E)$。辺の保存とUnion-Findの配列の保持 [cite: 19]。

**実装例 (C++)**:
```cpp
#include <iostream>
#include <vector>
#include <numeric>
#include <algorithm>

using namespace std;

// Union-Findの実装
struct UnionFind {
    vector<int> parent;
    UnionFind(int n) : parent(n) {
        iota(parent.begin(), parent.end(), 0); // 0からn-1で初期化
    }
    int root(int x) {
        if (parent[x] == x) return x;
        return parent[x] = root(parent[x]); // 経路圧縮
    }
    void unite(int x, int y) {
        int rx = root(x), ry = root(y);
        if (rx != ry) parent[rx] = ry;
    }
    bool same(int x, int y) {
        return root(x) == root(y);
    }
};

struct Edge {
    int u, v;
    long long cost;
    // コストでソートするための比較演算子
    bool operator<(const Edge& other) const {
        return cost < other.cost;
    }
};

long long kruskal(int V, vector<Edge>& edges) {
    sort(edges.begin(), edges.end()); // コスト昇順にソート
    UnionFind uf(V);
    long long min_cost = 0;
    
    for (const auto& e : edges) {
        if (!uf.same(e.u, e.v)) {
            uf.unite(e.u, e.v);
            min_cost += e.cost;
        }
    }
    return min_cost;
}
```

### 5.2 Prim法 (プリム法)

**説明**:
Dijkstra法に似たアプローチを取る。任意の1頂点からなる木を初期状態とし、現在の木に隣接する未訪問の頂点を結ぶ辺のうち、最もコストが小さいものを貪欲に追加していく [cite: 17, 20]。これをすべての頂点が木に含まれるまで繰り返す。実装にはDijkstra法と同様に優先度付きキューが用いられる [cite: 18, 20]。ノード間のコストが行列で与えられるような密なグラフに特に適している [cite: 18]。

**時間計算量**: $O(E \log V)$ （優先度付きキューを使用した場合）。優先度付きキューを使用せず、隣接行列を用いて毎回最小値を探す場合は $O(V^2)$ となり、密グラフではこちらの方が高速な場合もある [cite: 16, 20]。
**空間計算量**: $O(V + E)$。

**実装例 (Python)** [cite: 18]:
```python
import heapq

def prim(V, graph):
    # graph[u] = [(cost, v), ...]
    visited = [False] * V
    pq = [(0, 0)] # (cost, vertex) 初期頂点0
    min_cost = 0
    connected_count = 0
    
    while pq and connected_count < V:
        cost, u = heapq.heappop(pq)
        
        if visited[u]:
            continue
            
        visited[u] = True
        min_cost += cost
        connected_count += 1
        
        for next_cost, v in graph[u]:
            if not visited[v]:
                heapq.heappush(pq, (next_cost, v))
                
    return min_cost
```

## 6. トポロジカルソート (Topological Sort)

**説明**:
有向非巡回グラフ（Directed Acyclic Graph: DAG）の頂点を一列に並べる際、すべての有向辺が左から右へと向かうように順序付けるアルゴリズムである [cite: 21, 22]。タスクの依存関係（Aを終えないとBができない）を解決するスケジューリング問題や、DAG上での動的計画法（DP）を適用する前の順序付けとして極めて重要である [cite: 22, 23]。

トポロジカルソートには主に以下の2つの実装アプローチが存在する。
1.  **Kahnのアルゴリズム (BFSベース)**: 入次数（自身に向かってくる辺の数）が0の頂点をキューに入れ、キューから頂点を取り出しながら隣接する頂点の入次数を減らす。入次数が0になったものを順次キューに追加していく [cite: 4]。
2.  **DFSベース**: DFSを行い、帰りがけ（Post-order、頂点の探索が完全に終了したタイミング）に頂点をリストに追加し、最後にリストを反転させる [cite: 22, 23]。

**時間計算量**: $O(V + E)$。グラフ全体を一度だけ走査するため。
**空間計算量**: $O(V)$。入次数配列やキュー、結果を保持する配列を必要とする。

**実装例 (Kahnのアルゴリズム, C++)**:
```cpp
#include <iostream>
#include <vector>
#include <queue>

using namespace std;

vector<int> topological_sort(int V, const vector<vector<int>>& graph) {
    vector<int> in_degree(V, 0);
    // 各頂点の入次数を計算
    for (int u = 0; u < V; ++u) {
        for (int v : graph[u]) {
            in_degree[v]++;
        }
    }
    
    queue<int> q;
    // 入次数が0の頂点をキューに追加
    for (int i = 0; i < V; ++i) {
        if (in_degree[i] == 0) q.push(i);
    }
    
    vector<int> sorted_order;
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        sorted_order.push_back(u);
        
        for (int v : graph[u]) {
            in_degree[v]--;
            if (in_degree[v] == 0) {
                q.push(v);
            }
        }
    }
    
    // グラフに閉路(サイクル)がある場合、トポロジカルソートは不可能
    if (sorted_order.size() != V) {
        return {}; // サイクルあり
    }
    return sorted_order;
}
```

## 7. 強連結成分分解 (Strongly Connected Components: SCC)

**説明**:
有向グラフにおいて、任意の2頂点 $u, v$ について $u$ から $v$ への経路と $v$ から $u$ への経路が両方存在する（互いに行き来可能である）ような最大の頂点部分集合を「強連結成分（SCC）」と呼ぶ [cite: 21, 23]。グラフ内のすべての頂点を強連結成分ごとにグループ分けする操作が強連結成分分解である [cite: 23]。
SCCの非常に重要な性質として、各強連結成分を1つの大きな頂点とみなしてグラフを縮約（まとめる）すると、サイクルを含まないDAGが必ず構成される [cite: 21, 23]。これにより、複雑な有向グラフ上の問題を、まずSCCで分解し、縮約されたDAG上でトポロジカルソートやDPを行うというアプローチが可能になる [cite: 22, 23]。また、論理学における2-SAT（充足可能性問題）を解くアルゴリズムのコアとしても利用される [cite: 22]。

SCCを行う代表的なアルゴリズムには「Kosarajuのアルゴリズム」と「Tarjanのアルゴリズム」がある。ここでは直感的に理解しやすく実装も容易なKosarajuのアルゴリズムを解説する [cite: 23]。

**Kosarajuのアルゴリズムの手順** [cite: 23]:
1.  元の有向グラフ $G$ に対してDFSを行い、探索が終了した（帰りがけの）順に頂点に番号を付与する（リストに追加する）。
2.  グラフ $G$ のすべての辺の向きを逆にした逆グラフ $G_{rev}$ を構築する。
3.  手順1で付与された番号が大きい頂点（帰りがけ順が後だった頂点）から順に、未訪問であれば $G_{rev}$ 上でDFSを行う。この1回のDFSで到達できた頂点集合が1つの強連結成分となる。

**時間計算量**: $O(V + E)$。DFSを2回行うだけで完結するため、非常に高速である [cite: 23]。
**空間計算量**: $O(V + E)$。元のグラフ、逆グラフ、訪問状態配列などを保持する。

**実装例 (C++)**:
```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

void dfs1(int u, const vector<vector<int>>& graph, vector<bool>& visited, vector<int>& order) {
    visited[u] = true;
    for (int v : graph[u]) {
        if (!visited[v]) dfs1(v, graph, visited, order);
    }
    order.push_back(u); // 帰りがけ順
}

void dfs2(int u, const vector<vector<int>>& rev_graph, vector<bool>& visited, vector<int>& component) {
    visited[u] = true;
    component.push_back(u);
    for (int v : rev_graph[u]) {
        if (!visited[v]) dfs2(v, rev_graph, visited, component);
    }
}

// 戻り値: 強連結成分ごとの頂点リストのリスト
vector<vector<int>> scc(int V, const vector<vector<int>>& graph) {
    vector<vector<int>> rev_graph(V);
    for (int u = 0; u < V; ++u) {
        for (int v : graph[u]) {
            rev_graph[v].push_back(u);
        }
    }
    
    vector<bool> visited(V, false);
    vector<int> order;
    
    // 1回目のDFS
    for (int i = 0; i < V; ++i) {
        if (!visited[i]) dfs1(i, graph, visited, order);
    }
    
    fill(visited.begin(), visited.end(), false);
    vector<vector<int>> components;
    
    // 2回目のDFS (帰りがけ順の逆から)
    for (int i = V - 1; i >= 0; --i) {
        int u = order[i];
        if (!visited[u]) {
            vector<int> component;
            dfs2(u, rev_graph, visited, component);
            components.push_back(component);
        }
    }
    return components;
}
```

## 8. ネットワークフロー (Network Flow)

ネットワークフロー（最大流問題）は、ある始点（ソース: $s$）から終点（シンク: $t$）に向かって、各辺に設定された容量（Capacity）の制限を超えないようにどれだけ多くの「フロー（流量）」を流せるかを求める問題である [cite: 24]。

競技プログラミングにおいて、最大流アルゴリズムの実装として最もよく用いられるのは **Dinic（ディニッチ）法** である [cite: 2, 7, 24]。Ford-Fulkerson法も基礎として重要であるが、実用上はDinic法が圧倒的に高速である。

### 8.1 Dinic法 (ディニッチ法)

**説明**:
Dinic法は、以下の2つのフェーズを繰り返して最大流を求める [cite: 7, 24]。
1.  **レベルグラフの構築 (BFS)**: 残余グラフ（まだ容量に余裕がある辺と、流したフローを押し戻すための逆辺からなるグラフ [cite: 24]）上で、ソース $s$ から各頂点への最短距離（レベル）をBFSで計算する。シンク $t$ へ到達できなければ終了する [cite: 7]。
2.  **ブロッキングフローの探索 (DFS)**: 構築されたレベルグラフ上（始点から終点に向かってレベルが1ずつ増える辺のみを使用）で、DFSを用いて増加パス（フローを流せる経路）を見つけ、流せる限界までフローを流す。増加パスが見つからなくなるまで繰り返す [cite: 7, 24]。

「最大フロー最小カット定理」により、求まった最大流量は、ソースとシンクを分断するために切断すべき辺の容量の最小和（最小カット）と等しくなる。これも競プロで頻出の概念である [cite: 24]。

**時間計算量**:
*   一般的なグラフ: 最悪 $O(V^2 E)$ [cite: 24, 25]。しかし、実世界のネットワークや競プロのランダムケースでは理論値よりもはるかに高速に動作することが多い [cite: 7, 24]。
*   容量がすべて1の単位ネットワーク（二部マッチングなど）: $O(E \sqrt{V})$ と劇的に高速化される [cite: 24, 25]。

**空間計算量**: $O(V + E)$。グラフ、逆辺、レベル配列などを保持する。

**実装例 (C++)**:
```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <algorithm>

using namespace std;

const long long INF = 1e18;

struct Edge {
    int to;
    long long cap;
    int rev; // 逆辺のインデックス
};

class Dinic {
    int V;
    vector<vector<Edge>> graph;
    vector<int> level;
    vector<int> iter; // DFSでの探索済みの辺を記録

    void bfs(int s) {
        fill(level.begin(), level.end(), -1);
        queue<int> q;
        level[s] = 0;
        q.push(s);
        while (!q.empty()) {
            int v = q.front();
            q.pop();
            for (const auto& e : graph[v]) {
                if (e.cap > 0 && level[e.to] < 0) {
                    level[e.to] = level[v] + 1;
                    q.push(e.to);
                }
            }
        }
    }

    long long dfs(int v, int t, long long f) {
        if (v == t) return f;
        for (int& i = iter[v]; i < graph[v].size(); ++i) {
            Edge& e = graph[v][i];
            if (e.cap > 0 && level[v] < level[e.to]) {
                long long d = dfs(e.to, t, min(f, e.cap));
                if (d > 0) {
                    e.cap -= d;
                    graph[e.to][e.rev].cap += d; // 逆辺の容量を増やす
                    return d;
                }
            }
        }
        return 0;
    }

public:
    Dinic(int V) : V(V), graph(V), level(V), iter(V) {}

    void add_edge(int from, int to, long long cap) {
        graph[from].push_back({to, cap, (int)graph[to].size()});
        graph[to].push_back({from, 0, (int)graph[from].size() - 1});
    }

    long long max_flow(int s, int t) {
        long long flow = 0;
        while (true) {
            bfs(s);
            if (level[t] < 0) return flow; // tに到達できなくなったら終了
            fill(iter.begin(), iter.end(), 0);
            long long f;
            while ((f = dfs(s, t, INF)) > 0) {
                flow += f;
            }
        }
    }
};
```

## 9. 二部グラフと最大マッチング (Bipartite Matching)

**説明**:
頂点集合を2つの独立したグループ $L$ と $R$ に分割でき、すべての辺が $L$ の頂点と $R$ の頂点を結んでいるグラフを二部グラフ（Bipartite Graph）と呼ぶ [cite: 2, 26]。
二部グラフにおけるマッチングとは、端点を共有しない（同じ頂点を2回以上使わない）辺の集合のことである。マッチングの辺の数が最大となるようなものを見つける問題を「最大二部マッチング」と呼ぶ [cite: 26, 27]。
この問題は、男女のペアリング、タスクの割り当て、広告とユーザの最適化など、実世界で非常に幅広く応用される [cite: 2]。

**ネットワークフローへの帰着**:
二部マッチングは、前述の最大流問題に帰着させて解くのが最も典型的である [cite: 2, 26]。
1.  新たなソース（始点）$s$ とシンク（終点）$t$ を追加する。
2.  $s$ からグループ $L$ のすべての頂点へ、容量1の有向辺を張る [cite: 26]。
3.  グループ $L$ とグループ $R$ を結ぶ元の辺を、 $L$ から $R$ への容量1の有向辺とする [cite: 26]。
4.  グループ $R$ のすべての頂点から $t$ へ、容量1の有向辺を張る [cite: 26]。
この構築されたネットワークに対して最大流アルゴリズム（Dinic法など）を実行すると、得られた最大流量が最大マッチングの数と完全に一致する [cite: 26]。

**時間計算量**:
Dinic法を用いた場合、二部マッチングのネットワークでは計算量が $O(E \sqrt{V})$ となることが証明されており、非常に高速に動作する [cite: 24, 25]。

## 10. その他競技プログラミングで重要なグラフアルゴリズム

### 10.1 最小共通祖先 (Lowest Common Ancestor: LCA)

**説明**:
根付き木において、与えられた2つの頂点 $u$ と $v$ に対して、両方を子孫に持つような共通の祖先の中で、最も深い（最も葉に近い）頂点を求めるアルゴリズムである [cite: 28]。木構造上の2頂点間の距離を求めるクエリ（$\text{dist}(u, v) = \text{depth}[u] + \text{depth}[v] - 2 \times \text{depth}[\text{LCA}(u, v)]$）などに応用される [cite: 29]。

LCAを高速に求める手法として、**ダブリング（Doubling）** が非常に有名である [cite: 29, 30]。
各頂点について、「$2^k$ 個上の親」を事前計算してテーブルに保持しておく（$O(V \log V)$）。クエリに対しては、まず2頂点の深さを揃え、その後二分探索のようにして2頂点の親が一致する直前まで同時に遡り続けることで、高速にLCAを特定する（$O(\log V)$） [cite: 29, 30]。

その他、オイラーツアー（Euler Tour Technique）を用いて木を一次元の配列に落とし込み、RMQ（Range Minimum Query）問題に変換してSparse Tableやセグメント木で解く手法も存在し、こちらはクエリ $O(1)$ を実現可能である [cite: 31, 32]。

**時間計算量 (ダブリング)** [cite: 29]:
*   前処理: $O(V \log V)$
*   クエリ: 1回あたり $O(\log V)$
**空間計算量**: $O(V \log V)$。ダブリングテーブルの保存に必要 [cite: 29]。

**ダブリングの概念的コード (C++)**:
```cpp
// V: 頂点数, logV: Vの対数 (例えば V=100000 なら logV=17程度)
// parent[k][v] は頂点vの2^k個上の親を保持する
int LCA(int u, int v, int logV, vector<vector<int>>& parent, vector<int>& depth) {
    // 常に u の方が深いようにする
    if (depth[u] < depth[v]) swap(u, v);
    
    // 深さを揃える
    for (int k = logV - 1; k >= 0; --k) {
        if ((depth[u] - depth[v]) >> k & 1) {
            u = parent[k][u];
        }
    }
    
    if (u == v) return u;
    
    // LCAの直前まで遡る
    for (int k = logV - 1; k >= 0; --k) {
        if (parent[k][u] != parent[k][v]) {
            u = parent[k][u];
            v = parent[k][v];
        }
    }
    
    // 1つ上がLCA
    return parent[u];
}
```
